# Cadence for iOS

A native SwiftUI companion (iOS 26+): check in by text or on-device voice, review drafts with every check behind them, approve in two taps, see Results in Swift Charts, get a push when drafts are ready, and glance at a home-screen widget. The server does all the thinking; the app is a client of the [API](API.md).

## Run it

```bash
pnpm demo                 # the server, in demo mode, at http://localhost:3000
pnpm ios:gen              # generate the Swift API client from docs/openapi.json, then the Xcode project (XcodeGen)
pnpm ios:build            # build for the iPhone simulator
pnpm ios:unit             # CadenceKit unit tests (PKCE, sign-in, refresh, snapshot)
pnpm ios:test             # UI test (quarantined: set CADENCE_UITEST=1; see UITests/CadenceUITests.swift)
open ios/Cadence.xcodeproj
```

Debug builds talk to `http://localhost:3000`; Release builds to `CADENCE_SERVER_URL` in `ios/project.yml`.

## How it fits together

| Piece | What |
|---|---|
| `ios/CadenceKit` → `CadenceAPI` | Swift client generated by Apple's `swift-openapi-generator` from `docs/openapi.json` (committed; CI checks it's current) |
| `ios/CadenceKit` → `CadenceCore` | OAuth 2.1 sign-in (dynamic registration, PKCE, resource = `/api/v1`, refresh), Keychain storage, auth middleware (bearer, one refresh on 401, problem+json → readable errors), the widget snapshot |
| `ios/App` | SwiftUI screens: welcome, subscribe (US link-out), setup (web), This week, draft + why, edit, check-in (voice via `SpeechAnalyzer`), Results (Swift Charts), Settings (delete account) |
| `ios/Widgets` | Small and medium "This week" widget, reading the App Group snapshot |

**Sign-in** opens Cadence's own web sign-in in `ASWebAuthenticationSession` (LinkedIn, Sign in with Apple, or the App Review login), then the consent screen. The app never sees a LinkedIn or Apple password.

**Subscribing** happens on the web (US storefront link-out), in the same secure browser session, which returns to the app with `app.cadence.ios://subscribed`. New users then do the one-time setup the same way.

**Approving** always shows the exact text and the slot first; tokens without the `approve` scope explain how to allow it. Notifications only open screens.

## Checked on the simulator (iPhone 18 Pro, iOS 27, 2026-09-27)

Sign-in with registration and consent → the link-out → demo trial → setup → back in the app → check-in → drafts → why sheet → approve (scheduled) → notification permission → device registered with the server → simulated push shown → Results. The automated UI test is quarantined (named cause in `ios/UITests/CadenceUITests.swift`: the iOS 27 simulator's sign-in sheet can't be driven reliably by XCUITest); the server side of sign-in is covered by `e2e/ios-oauth.spec.ts`. Not yet checked: voice (on-device speech isn't available in the simulator; needs a real iPhone), the widget on a home screen, and real APNs delivery (needs the APNs key).
